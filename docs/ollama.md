# Локальный AI через Ollama

В 0.5.0 Ollama — отдельный провайдер того же игрового агента. Снимок мира поступает встроенной службе, она запрашивает локальную модель, проверяет JSON-план и выдаёт моду штатные действия. Управление из чата, 40 исполнителей, стоп/F9 и журнал сохраняются. Отдельный агент или пусковой PowerShell не нужен.

## Подключение в игре

1. Установите/запустите [Ollama](https://ollama.com/download) **на том же ПК, где работает клиент помощника**. Загрузите текстовую instruct/chat-модель через Ollama. Наличие приложения без загруженной модели недостаточно.
2. Обновите всю папку BepInEx из Windows ZIP, включая runtime/_internal. Войдите в мир и откройте Esc → «Управление персонажем» → «Подключение AI».
3. Кнопкой провайдера выберите **Ollama (локально)**. Вместо API-ключа появится адрес; по умолчанию `http://127.0.0.1:11434`.
4. «Получить модели» покажет установленные локальные модели. Выберите точное имя, включая тег: например `qwen2.5:3b`. Мод не скачивает модели автоматически.
5. Нажмите «Проверить модель». Проверка использует настоящий формат JSON-плана с тестовым наблюдением, без данных вашего персонажа. При первой загрузке может потребоваться до 5 минут.
6. Сохраните подключение. В «Персонаж» включите AI и давайте поручения через игровой чат: «Бъерн, подбери камни». Используйте настоящее имя персонажа помощника. F9 немедленно возвращает ручное управление и отменяет ожидающие запросы, включая проверку модели.

Адрес и выбранная модель сохраняются в обычной конфигурации. Для Ollama ключ не требуется после перезапуска службы. Саму Ollama нужно держать запущенной; мод завершает только собственную службу AI. Модели и Ollama не входят в игровой ZIP.

## Размышления отключены

Каждый `/api/chat`, включая диагностику и разбор обычного чата, отправляется с **`think: false`**. При метаданных, требующих обязательные размышления, проверка останавливается с объяснением. Перехода на `low`/другой reasoning-режим нет. Выберите модель, поддерживающую отключение reasoning. Поля внутренних размышлений не используются как действия и не выводятся в журнал.

## Скорость и качество

Локальное выполнение не расходует квоту Google/OpenAI. Нагрузка приходится на ваш CPU/GPU и память, которые также использует Valheim. Слишком большая модель может замедлить игру или не загрузиться. Очень маленькая модель может выдавать правильный JSON, но неверно понимать поручения: прохождение проверки формата не доказывает качество агента.

По умолчанию запрос использует контекст 16K, `temperature=0`, максимум 2048 выходных токенов и короткие планы из 1–3 действий. Локальное наблюдение уплотняется: сохраняются все ID предметов инвентаря, основные характеристики/ограничения, ближайшие сущности и часть рецептов/деталей. Перед исполнением каждый шаг проверяется по полному свежему снимку. Вымышленный предмет/недоступное действие не исполняется.

Аргументы JSON обязательны, включая количество вещей: модель должна явно указать `amount`, а не полагаться на значение 1. Новая генерация действий с побочными эффектами ждёт подтверждения текущего шага. Если во время ответа завершилось игровое действие, план по старому состоянию отбрасывается; это предотвращает повторный сброс/крафт из-за медленной модели. Сопровождение/ожидание и новые обращения продолжают обрабатываться фоново.

Интервал решений остаётся 20 секунд по умолчанию. Медленная модель обрабатывает один план за раз; снимки и движение по актуальному плану продолжаются между ответами. Первый запуск холодной модели обычно медленнее повторных. Ожидание генерации — до 300 секунд, UI — 310. Во время явной проверки новая фоновая генерация не запускается.

## Диагностика

- «Ollama не запущена»: запустите приложение и проверьте адрес/порт. При стандартной установке это 11434.
- Пустой список: загрузите локальную текстовую модель через Ollama и обновите список. Облачные теги исключаются; облачного переключения нет.
- 404: точного имени нет среди установленных моделей либо указан неправильный порт/API. Сравните с `ollama list`.
- Нет поддержки текста/JSON/отключения thinking: выберите совместимую instruct/chat-модель и обновите Ollama.
- Недостаточно памяти: выберите меньшую модель; повторная автоматическая загрузка при такой ошибке останавливается.
- Долгое ожидание: первая загрузка/CPU-генерация, занятая память или очередь Ollama. F9 отменяет ожидание. При 503 есть пауза перед новым циклом.
- Качество поведения: начните с простого поручения, проверьте журнал фактических действий. Смена модели может быть важнее изменения интервала запросов.

Для этой версии поддерживаются HTTP-адреса loopback (`127.0.0.1`, `localhost`, `::1`), включая другой локальный порт. Ollama на другом компьютере/LAN пока не поддерживается. Адрес не принимает логин/пароль, путь, query или перенаправление. Облачные API-ключи не отправляются локальному серверу; скрытого отката к платному провайдеру нет.

В основе адаптера — официальные [API chat](https://docs.ollama.com/api/chat), [список моделей](https://docs.ollama.com/api/tags), [JSON schema](https://docs.ollama.com/capabilities/structured-outputs) и [настройка thinking](https://docs.ollama.com/capabilities/thinking).
