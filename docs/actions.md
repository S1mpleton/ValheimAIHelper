# Действия и проверка персонажа — 0.6.0

AI выбирает короткий план. Мод выполняет штатные движения, взаимодействия и операции инвентаря, затем отправляет фактический результат. Ни один ответ модели сам по себе не подтверждает успех. Все ID и количества проверяются мостом и повторно модом по свежему снимку.

## Предметы и инвентарь

В наблюдение входят все стопки личного инвентаря: ID, локализованное имя, количество, вес, экипировка, пригодность еды, характеристики и прочность. Наземные `kind=item` берутся из реестра загруженных игрой `ItemDrop` с действительным `ZNetView`. Это выпавшие вещи с игровым эффектом подсветки; растения, декорации и содержимое закрытых сундуков не выдаются за выпавшие вещи.

Обзор выпавших вещей — до **128 м**, пока объекты загружены клиентом; это ограничение AI, а не настройка графической дальности игры. Передаются ближайшие **80 стопок**, их реальные количества, вес, позиции и текущая возможность подбора. Общее число и факт сокращения также передаются. Ollama больше не обрезает этот список второй раз. Скрытые или ещё не загруженные сетевые объекты не доступны. Препятствие может сделать видимый предмет недостижимым.

| Действие | Из чего состоит | Команда для проверки |
|---|---|---|
| `pickup` | Найти выпавший ItemDrop → проложить путь → подойти → при необходимости запросить владение штатным RPC → проверить место/вес → штатный Pickup → подтвердить прирост инвентаря | «Гоша, подбери камни рядом» |
| `drop` | Найти стопку в своём инвентаре → проверить количество → DropItem → подтвердить уменьшение стопки | «Гоша, сбрось 5 камней» |
| `give` | Найти игрока и предмет → подойти к текущей позиции игрока → остановиться в пределах 2,5 м → повернуться к нему → сбросить точное количество → подтвердить уменьшение инвентаря | «Гоша, дай мне 5 камней» |
| `open` | Подойти к сундуку → штатное открытие → дождаться доступа → отправить содержимое в следующем наблюдении | «Гоша, открой этот сундук» |
| `take` | После открытия выбрать ID из содержимого → штатная передача в личный инвентарь → проверить результат | «Гоша, возьми 3 камня из сундука» |
| `deposit` | После открытия выбрать ID из личного инвентаря → штатная передача в сундук → проверить результат | «Гоша, положи 3 камня в сундук» |
| `stack` | Открыть доступный сундук → штатная кнопка складывания совпадающих стопок | «Гоша, сложи в сундук совпадающие предметы» |
| `close` | Закрыть контейнер и освободить собственную сессию игрового инвентаря | «Гоша, закрой сундук» |
| `equip`, `unequip` | Выбрать предмет → штатная экипировка/снятие → проверить состояние | «Гоша, возьми дубину в руки» |
| `eat`, `use` | Проверить CanEat/тип расходника → штатное UseItem → проверить изменение | «Гоша, поешь» |
| `use_on` | Подойти к печи/костру/станции → применить подходящий предмет из сумки → дождаться принятия игрой | «Гоша, добавь уголь в плавильню» |

`give` не кладёт предмет непосредственно в чужой инвентарь: он остаётся на земле рядом с получателем, и тот подбирает его обычным способом. Если путь недоступен или получатель исчез, сброса вдали от него не происходит. Квестовые вещи не сбрасываются. Если вещей мало, модель должна объяснить нехватку; большего, чем есть в указанной стопке, мод не сбросит. Для нескольких стопок нужен план из нескольких операций с их реальными ID.

Подбор использует целую выпавшую стопку, если хватает места и переносимого веса. Для поручения «подбери, затем дай» модель сначала подбирает, получает новый ID предмета из инвентаря и только затем планирует передачу. Один ID с земли нельзя использовать как ID сумки. После последнего подтверждённого `give`/`drop` поручение завершается автоматически, чтобы модель не повторяла передачу в каждом цикле.

Всего в каталоге **41 действие**, включая перечисленные выше. Настройки боя/строительства могут уменьшать фактически разрешённый набор.

| Действия | Состав и ограничения |
|---|---|
| `wait` | Пауза, затем свежее наблюдение |
| `follow` | Найти выбранного лидера → проложить маршрут → двигаться → поддерживать дистанцию |
| `move`, `jump` | Короткое движение к точке до 30 м либо вперёд; прыжок штатным вводом, проверка высоты и выносливости |
| `look` | Повернуться к заданной близкой точке |
| `attack`, `secondary_attack` | Подойти к враждебной цели → прицелиться → штатная основная/вторичная атака; учитываются оружие, дистанция, выносливость |
| `defend`, `dodge`, `flee` | Повернуться и блокировать; уклониться; отступать от угрозы |
| `hunt` | Подойти/атаковать дикое неприручённое животное; бой должен быть разрешён |
| `gather` | Подойти к дереву/ресурсу → проверить топор/кирку и уровень инструмента → штатные удары; добытый лут подбирается отдельным `pickup` |
| `interact` | Подойти к растению/двери/другому наблюдаемому интерактивному объекту → штатное Interact |
| `craft`, `upgrade` | Проверить известный рецепт, ресурсы и станцию → выполнить крафт/улучшение через игровой интерфейс → проверить результат |
| `repair` | Подойти к доступной станции → штатный ремонт снаряжения |
| `build`, `repair_building` | Выбрать деталь/молот → навести штатный предпросмотр → проверить позицию → выполнить штатное размещение/ремонт |
| `hide_weapon`, `show_weapon` | Убрать/достать предметы в руках |
| `sneak`, `unsneak` | Включить/выключить скрытное движение |
| `rest`, `stand` | Сесть для отдыха в подходящих условиях; встать/прекратить жест или сидение |
| `sleep` | Подойти к собственной кровати → штатное взаимодействие; игра проверяет условия сна |
| `guardian_power` | Штатная активация силы Хранителя с её обычным восстановлением |
| `emote` | Штатный жест из разрешённого набора |
| `speak` | Одно сообщение в игровой чат; подтверждённый ответ запоминается |

## Последовательность ручной проверки

1. Обновите **всю папку BepInEx** из ZIP при закрытой игре. Запустите Ollama, в игре выберите модель, проверьте и сохраните её. Включите AI. Используйте настоящее имя персонажа помощника вместо «Гоша»; команда приходит от разрешённого игрока.
2. Положите помощнику 12 камней, отойдите на 10–15 м: «Гоша, дай мне 5 камней». Должны прийти подтверждение принятия, движение и сообщение о сбросе. У помощника остаётся 7; рядом с вами появляются 5. Подождите два цикла AI: повторной передачи быть не должно.
3. «Гоша, сбрось 2 камня». Он сбрасывает у себя, остаток — 5. «Дай 99 камней» не должен создавать вещи или сбрасывать больше наличия; проверьте причину в чате/журнале.
4. Бросьте несколько разных вещей в 5–40 м: «Гоша, подбери выпавшие предметы». Проверьте подход и фактический прирост сумки. Повторите при заполненной сумке/почти полном весе, за закрытым препятствием и заберите цель другим игроком во время подхода: ожидается объяснение отказа.
5. «Гоша, какие вещи у тебя есть?» — ответ должен соответствовать текущим стопкам. Сравните с разделами Inventory/Dropped items скопированного отчёта.
6. Проверьте доступный сундук: открыть → взять → положить → сложить совпадающие → закрыть. Замок, занятость другим игроком, отсутствие места или материалов должны давать штатный отказ.
7. Во время ответа откройте «Журнал»: виден счётчик ожидания, затем время запроса, токены/с, загрузка, обработка входа и генерация. Переключите модель: журнал `ollama-memory` и `ollama ps` должны показать выгрузку остальных ранее загруженных моделей. F9 должен отменить управление и ожидание.

Автотесты проверяют протокол, цели, количества, смену моделей, обратную связь и временные показатели. Отдельно проверен настоящий Ollama/qwen3:1.7b. В облаке нет запущенной Valheim 1.0.21: движение, реальные сетевые RPC и операции инвентаря внутри игры требуют этой ручной проверки. Валидная схема улучшает выбор аргументов, но не гарантирует понимание всех формулировок маленькой моделью.
