# Valheim AI Helper 0.8.3

Обновление исправляет обмен с инвентарём NPC, имя отправителя в чате и обработку изменений задач. Архитектура остаётся **один клиент + NPC**; PowerShell, отдельный Python и второй игровой клиент для готового Windows-архива не нужны.

- **Собственный отправитель в чате.** Ответы AI и действие `speak` идут от игрового объекта NPC с его именем, отдельным надголовным сообщением и сохранёнными штатными проверками отправителя. Владелец мода и другие клиенты с модом видят «Гоша: [AI] …»; ответы NPC не поступают обратно как команды человека. Для такого имени в журнале чата другого участника мод нужен и на его клиенте: стандартный журнал клиента без мода может разрешать имя по аккаунту хоста.
- **Броня NPC.** В штатном окне обмена у ячеек NPC появляется отдельный значок щита с его бронёй. В резервном окне значение показано у заголовка сумки. Значение берётся из игрового расчёта надетой брони с учётом качества и эффектов; показатель человека не заменяется.
- **Временная остановка на время обмена.** Инвентарь больше не отправляет постоянный стоп задач. Пока он открыт, ввод NPC и исполнение приостановлены; после закрытия прежняя работа продолжается по свежему наблюдению. Сохраняются режим, пул и подтверждения операций с вещами. F9, ручная пауза, смена провайдера, смерть и выход из мира не отменяются закрытием окна.
- **Изменение и отмена задач.** Полностью одинаковые изменения одного ID не вызывают ложный конфликт. Противоречивые изменения проверяются до принятия пула и могут быть исправлены моделью в единственном повторе `tasks-repair`. AI по-прежнему сам выбирает, какие задачи отменить, продолжить или изменить; словарь синонимов команд и автоматические приоритеты не добавлены.
- **Доступные атомарные цели.** Схема действий использует реальные ID подходящих врагов, вещей и объектов. Если врагов не видно, атака не предлагается как доступное действие; человек-лидер не становится целью атаки. В контексте инвентаря доступны признаки экипировки, еды, использования, брони и урона. Это помогает разобрать просьбы об экипировке и подготовке, но не гарантирует понимание любой фразы небольшой моделью.
- **Повтор при несовпадении передачи.** Если новый план передачи не совпал с независимым разбором исходной просьбы, модель может исправить весь набор задач. Исправленный вариант проверяется снова, с сохранением проверки количества, типов, квестовых предметов и отдельного разрешения на передачу всей сумки. Используется тот же единственный повтор в пределах исходного времени ожидания. Код не исправляет количество за AI и не исполняет неподтверждённую выдачу.

В присланном диалоге на «готовья к бою» модель дважды предложила атаковать ID человека. Это объясняет отказ конкретного плана, а не невозможность самой подготовки к бою. При отмене сбора журнал показал конфликт изменений одного ID. Сообщение о несовпадении передачи означает, что два разбора модели разошлись; без соответствующего сырого `task-transfer` нельзя утверждать, какой из них ошибся.

**[Полный список 38 действий NPC с условиями](https://github.com/S1mpleton/ValheimAIHelper/blob/main/docs/actions.md)**. Отдельно описаны шесть типов задач `follow`, `collect`, `give`, `drop`, `action`, `goal` и изменения `cancel`, `pause`, `resume`, `priority`.

Для обновления закройте игру и скопируйте **всю папку BepInEx из ZIP** в каталог с `valheim.exe` с заменой файлов плагина, включая `runtime/_internal`. Не удаляйте `BepInEx/config` с настройками и пулами задач. Уберите старую отдельную `BepInEx/plugins/ValheimAIHelper.dll`, если она осталась вне папки плагина. В отчёте должна быть версия **0.8.3**. Если пул уже остался на постоянной паузе после 0.8.2, один раз нажмите **«Задачи → Продолжить всё»**; обновление не отменяет сохранённые паузы. Затем обычное закрытие обмена продолжает работу автоматически, без подключения модели заново.

Проверьте в игре: броню после надевания туники; имя NPC в сообщении; продолжение работы после обмена без повторного подключения; сохранение стопа F9 при закрытии окна; «прекращай собирать» с сохранением следования; передачу одного камня при известном остатке. При проблеме приложите общий отчёт и соответствующие фазы `tasks`, `tasks-repair`, `task-transfer` из «Журнал → Диалог AI».

Результаты автоматических проверок записываются в [validation.md](https://github.com/S1mpleton/ValheimAIHelper/blob/main/docs/validation.md). Valheim 1.0.21 в среде разработки недоступен: физика, внешний вид игрового окна и кооператив требуют проверки в установленной игре. Ollama во всех запросах сохраняет `think=false`; API-ключи остаются в памяти службы. Windows ZIP публикуется CI после прохождения проверок Linux и Windows.
