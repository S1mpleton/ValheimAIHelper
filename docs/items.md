# Каталог и выбор предметов — 0.7.4

Мод строит каталог из `ObjectDB` запущенной игры: берёт корректные prefab с `ItemDrop`, включая предметы, зарегистрированные другими модами. Список зависит от установленной версии игры и набора модов. Предметы не создаются и таблицы случайного лута при построении каталога не разыгрываются.

## Полный список

После загрузки базы игры каталог сохраняется в:

```text
BepInEx/config/ValheimAIHelper/item-catalog.json
```

Файл содержит версию игры, язык, версию каталога, общее число типов `total` и массив `items`, отсортированный по `item_prefab`. Запись заменяется целиком после успешной подготовки нового файла, чтобы ошибка записи не оставляла обрезанный каталог.

| Поле записи | Значение |
|---|---|
| `item_prefab` | Техническое имя типа из игры, например `Stone`, `Raspberry`, `Resin`, `AxeStone` |
| `name` | Название на текущем языке игры |
| `token` | Исходный токен локализации, например `$item_stone` |
| `category` | Категория из игровых данных ItemDrop |

Это описание **типов вещей**. Наличие `AxeStone` в каталоге не означает, что топор есть у NPC или лежит поблизости. Содержимое закрытых сундуков, незагруженные предметы и позиции всех вещей мира каталог не раскрывает.

## Что получает AI

У вещей в сумке и на земле есть `item_prefab` и `item_token` наряду с ID конкретного предмета, количеством и свойствами. У уже наблюдаемого собираемого растения поле `produces` указывает объявленный тип урожая. Например, куст малины связан с `Raspberry`; выпавшая малина определяется по типу самого ItemDrop.

Снимок передаёт не больше 4096 определений, а поля `item_catalog_total` и `item_catalog_truncated` показывают полное число и факт усечения. Экспорт JSON содержит весь каталог. Служба сохраняет полученную версию и подтверждает её: после подтверждения мод передаёт только версию, без повторения большого массива в каждом снимке. При перезапуске службы или изменении каталога передача повторяется.

Для передачи каталога лимит тела запроса `/api/decision` увеличен до 2 МиБ. На остальных HTTP-маршрутах сохраняется лимит 128 КиБ. После подтверждения каталога обычные снимки снова отправляются без большого массива типов.

В запрос Ollama для разбора нового поручения попадают до 48 наиболее подходящих определений каталога и все типы из фактического наблюдения. Отдельно перечисляется наблюдаемый запас. Содержимое базы типов не считается доступным запасом. Ресурсам наподобие смолы не приписываются неприменимые характеристики брони, блока и навыка мечей.

## От поручения к действию

1. **Модель разбирает смысл:** собрать, передать, сбросить, ответить на вопрос либо выполнить общее поручение; выбирает типы предметов и количество. Синонимы и контекст по-прежнему обрабатывает нейросеть.
2. **Служба сверяет доступность:** собственная сумка, наблюдаемые выпавшие вещи и урожай наблюдаемого растения. Для плана остаются подходящие действия и ID целей.
3. **Модель выбирает действие** в этих пределах. Служба проверяет соответствие типу предмета и количеству; мод повторно проверяет реальные условия перед выполнением.
4. **Исполнитель проверяет результат:** подход, сбор/передача и фактическое изменение инвентаря используют существующие игровые действия. Если подходящей цели нет, помощник даёт один ответ с причиной и ждёт нового поручения.

Если разбор выбрал `all_inventory`, отдельная короткая проверка `item-scope` уточняет, запрошена ли вся сумка. Если этот выбор не подтверждён, допускается один повтор разбора с исключённым вариантом `all_inventory`; первая ошибочная массовая передача не исполняется. Для обычного точного количества и `all_matching` дополнительная проверка всей сумки не вызывается. Она также выполняется нейросетью, без словаря всех синонимов в моде.

Примеры для проверки:

| Поручение | Допустимая цель |
|---|---|
| «Подбери топор» | Выпавший топор подходящего типа; при отсутствии — сообщение об отсутствии |
| «Собери малину» | Наблюдаемый куст с урожаем `Raspberry` или уже выпавшая малина |
| «Дай три камня» | Камни из сумки NPC, точное количество 3 |
| «Отдай все камни» | Все подходящие стопки камней в сумке |
| «Отдай все свои вещи» | Составная передача допустимых вещей инвентаря |

В присланном отчёте топора не было среди восьми выпавших предметов и в сумке NPC. Каталог позволяет назвать такой тип, но для его подбора всё равно нужен реальный наблюдаемый топор. Выбор костра для такого поручения должен отклоняться.

Разбор добавляет короткий запрос Ollama для нового поручения; повторные наблюдения задачи используют кеш. Все запросы выполняются с `think=false`. В **Журнал → Диалог AI** этап помечен `item-intent`, отдельно от плана; проверка всей сумки помечена `item-scope`. При неверном выборе сохраните все этапы: неверно понятый тип и неверное исполнение требуют разной диагностики. Ограниченный формат ответа не гарантирует понимания любой формулировки небольшой моделью.

Скорость и числа токенов суммируются по всем этапам текущего плана, включая разбор предмета и проверку массовой передачи. Пауза в настройках относится к новым планам; разбор текущей цели кешируется.
