# Один клиент + NPC — 0.7.1

Один обычный клиент игры содержит человека и отдельного сетевого напарника. NPC использует стандартный humanoid/Player prefab Valheim для внешности, оружия, брони, физики, еды и навыков; локальным игроком он не становится. Второй Steam-аккаунт, подключение второго клиента и профиль персонажа из второго клиента не нужны.

## Запуск

Скопируйте весь Windows-дистрибутив и запустите свой мир одним персонажем. В Esc → «Управление персонажем» → «Персонаж» задайте имя NPC и нажмите «Создать / найти NPC». По умолчанию имя Гоша, лидер — локальный человек независимо от старой настройки имени второго клиента. Удалённый лидер выбирается явно и сохраняется по ID. Имя существующего NPC применяется этой же кнопкой. «Следовать» работает без AI; для смысловых поручений настройте модель и включите AI.

NPC создаётся только в одиночном мире либо клиентом-хостом. Подключившийся клиент получает объяснение, создание на чужом/выделенном сервере не производится. Мод устанавливается у хоста; используется обычный сетевой prefab Player. Физику и решения ведёт хост; NPC остаётся принадлежащим его сетевому узлу. Другие игроки наблюдают стандартную синхронизацию Valheim.

NPC появляется рядом на проверенной земле. Начальный инвентарь пуст. Чужой или старый профиль не копируется. Передайте ему вещи через землю и поручение «Гоша, подбери …». F9 останавливает NPC, человек продолжает управлять своим персонажем.

## Что сохраняется

Отдельный native Player.Save package записывается в ZDO NPC: инвентарь с качеством/вариантами/custom data, навыки, открытые рецепты, еда и игровые параметры. Запись обновляется при изменении инвентаря, примерно раз в секунду и перед сохранением мира. Положение сохраняет стандартный ZSync. Пакет и идентификатор NPC относятся к конкретному миру. Ключи AI в NPC не записываются.

В `BepInEx/config/ValheimAIHelper/companions/<world-id>.json` хранится вспомогательная запись. Перед созданием проверяются **все ZDO загруженного сохранения**, включая неактивные области; отсутствие/откат локального файла не разрешает дублировать NPC. Если существующий NPC не загружен, окно показывает место; вернитесь туда. Автоматической телепортации/призыва нет.

При смерти вещи перемещаются в отдельное надгробие с именем/ID NPC. Профиль, точка смерти и возрождение человека не меняются. Новый NPC создаётся явным нажатием кнопки, с пустым инвентарём. Надгробие остаётся в мире.

## Команды и передача

**«Следуй за мной»** — одна локальная фраза следования, с именем NPC либо без. «Гоша, пошли», «пойдём», «держись рядом» и другие формулировки выбирает по смыслу модель. F9 и именованный стоп немедленны. Пока модель готовит новое поручение, его синонимы не распознаются словарём в моде.

`give` — составное действие: проверить резерв вещей → построить маршрут к актуальному получателю → подойти на 2–2,5 м → повернуться → повторно проверить резерв/расстояние → вызвать штатный DropItem → измерить уменьшение инвентаря. Получатель подбирает оставленное обычным способом. Успех не означает, что предмет уже попал ему в сумку.

Параметр `selection` выбирает **модель**, мод исполняет выбранную операцию:

| Значение | Поведение | Пример |
|---|---|---|
| `exact` | Точное количество, при необходимости из нескольких одинаковых стопок | «Гоша, дай мне 7 камней» при стопках 5 + 3 |
| `all_matching` | Все стопки выбранного вида/качества/варианта | «Гоша, отдай все камни» |
| `all_inventory` | Все неквестовые вещи, включая экипированные | «Гоша, отдай мне все свои вещи» |

Для `drop` действуют те же варианты без подхода к получателю. Модель не должна перечислять 32 шага для передачи 32 стопок. Перед первой мутацией проверяется весь резерв; уменьшение количества по пути отменяет передачу. Если нативный сброс частично выполнился, сообщается реальное количество и требуется новое поручение на остаток: повтор исходного количества запрещён. Переданные вещи автоматически обратно не подбираются; обычный AutoPickup для NPC выключен.

## Навигация и ограничения

Используются полные пешие маршруты Pathfinding, повторный поиск при построении сетки, точки подхода рядом с целью, проверка перепадов и продвижения. Небольшое препятствие допускает штатный прыжок; после ограниченных повторов появляется причина отказа. Прямая запись положения/скорости вместо навигации не применяется. NPC не проходит через порталы и не телепортируется к лидеру.

Содержимое сундука читается только после проверки доступа/владения/расстояния и открытия собственной NPC-сессии. Окно InventoryGui игрока не используется. При открытии того же сундука человеком NPC уступает. Для первой NPC-версии требуется владение сундуком сетевым хостом; закрытые для NPC частные сундуки не обходятся.

Крафт/улучшение: выбрать известный рецепт → проверить станцию/материалы → дождаться операции → снова проверить → нативные методы инвентаря/расход ресурсов → подтвердить результат. Ремонт проверяет станцию, рецепт и уровень и меняет прочность только допустимого снаряжения. Рецепты с выбором одного из ингредиентов пока отклоняются. Камера и окна человека не используются.

NPC не объявляет `build`, `repair_building`, `sleep`: для них нужен новый исполнитель вместо старой зависимости от локальной камеры/кровати. NPC не мешает хосту спать и пропускать ночь. На остальных действиях сохраняются игровые ограничения. [Каталог и ручные проверки](actions.md).

Одному клиенту обычно нужно меньше CPU/RAM/VRAM, чем двум играм; удаляется отдельное сетевое соединение помощника. Скорость генерации Ollama всё равно зависит от модели и доступного оборудования. Наличие одного клиента само по себе не улучшает понимание маленькой моделью поручений.

Сборка/тесты без установленной игры не доказывают игровой запуск. Для Valheim 1.0.21 обязательны сценарии создания, сохранения/повторного входа, смерти, передачи нескольких стопок и наблюдения с другого официального клиента.
