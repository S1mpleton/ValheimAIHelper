# Проверка 0.7.4 и диагностика

## Предметы и открытие инвентаря 0.7.4

Эти сценарии требуют запуска настоящей игры. Автоматические проверки протокола, каталога и обработки нажатия не подтверждают отрисовку InventoryGui на Valheim 1.0.21.

1. После входа в мир найдите `BepInEx/config/ValheimAIHelper/item-catalog.json`. Проверьте `total`, язык, версию и записи `Stone`, `Raspberry`, `Resin`, `AxeStone`. ID должны быть отсортированы; локальные названия соответствовать выбранному языку. Установленный мод с зарегистрированным предметом должен добавлять его в каталог. Список зависит от текущей игры; вручную создавать вещи для каталога не требуется.
2. Дайте NPC обычные камни и смолу. В снимке вещи должны иметь разные `item_prefab` и `item_token`; у смолы не должно быть вымышленных характеристик брони, блока и навыка мечей. Попросите «дай один камень»: в `item-intent` должны быть Stone/точное количество, а в плане — предмет из сумки NPC.
3. Уберите топоры из сумки и наблюдаемой области. Попросите подобрать топор: ожидается один ответ с причиной отсутствия. Костёр, камень и другая вещь не должны становиться целью такого поручения. Затем положите выпавший топор рядом и повторите команду; проверяйте фактический `pickup` соответствующего ID.
4. Попросите собрать малину рядом с видимым кустом и посторонними вещами. Ожидается `interact` куста с `produces=["Raspberry"]` и затем `pickup` выпавших ягод, либо подбор уже лежащей малины. Камни и смола не должны подменять цель. При отсутствии ягод/куста нужен ответ с причиной.
5. Положите одуванчик первой вещью в сумке NPC, затем не меньше пяти камней. Сравните «дай 5 камней», «отдай все камни» и «отдай все свои вещи», включая перефразировки. Первое поручение должно передавать ровно пять камней и сохранять одуванчик. В диалоге AI должны быть `item-intent` с типами/количеством и план; выбор всей сумки дополнительно проверяется в `item-scope`. При отклонении массового выбора допускается один повтор разбора без `all_inventory`, исходная передача не исполняется. Повторные снимки одной задачи используют кеш. `think` остаётся `false`.
6. Подойдите к живому NPC, наведите на него и нажмите E. Сравните с кнопкой «Инвентарь NPC» в меню. В журнале `npc-inventory` должны быть стадии E/запрос/открытие. Должны показываться обе сумки в штатном окне игры; проверьте перенос через Shift, разделение стопки, складывание, «Забрать всё», закрытие и сохранение после перезахода.
7. Откройте обычный сундук через E: его штатное поведение должно сохраниться. Набирайте E в чате и используйте меню: окно NPC открываться не должно. Повторите обмен с NPC при одинаковом имени человека и помощника; роли и идентификаторы в контексте AI должны различаться. За одно нажатие не должно быть двух попыток открытия. F9 останавливает NPC, а после закрытия обмена AI/следование сами не возобновляются.
8. Перезапустите локальную службу и продолжите работу: каталог должен передаться заново и получить подтверждение. Для большого каталога снимок допускает до 4096 типов и явно показывает усечение; JSON-файл содержит полный экспорт.

## Регрессии из отчёта 0.7.1

1. Включите AI и спросите по имени NPC: «Сколько у тебя вещей?». После одного ответа подождите минуту: тот же ответ не должен появляться снова, а генерации по завершённому вопросу — повторяться.
2. Дайте NPC одуванчик и 7 камней через инвентарь. Попросите дать один камень. В «Журнал → Диалог AI» должны быть читаемые `@bag/…` ID, а в результате — исходный ID камней. Сопоставьте распознанный тип в `item-intent`, выбранный предмет, землю и сумку. Если неверен сам распознанный тип, сохраните оба этапа ответа модели для диагностики.
3. После подтверждённой передачи подождите: повторной выдачи и возвращения к предыдущему сбору быть не должно. Новое поручение должно запускать новую обработку.
4. При одинаковом имени игрока и NPC проверьте роли/ID в контексте. Попросите рубить видимый пень с исправным топором: ожидается `gather` с ID ресурса; `interact` с грибом не является рубкой. Статус показывает фактически выбранную цель. Без пня/топора нужен ответ с причиной.
5. Ответ модели, буквально повторяющий вопрос или одну фразу много раз, должен отклоняться с причиной. Нормальный ответ с количеством предметов должен проходить.
6. После смерти NPC отчёт должен показывать «NPC не загружен», а старую сумку — только как последний снимок. Проверьте надгробие. Текущая сумка живого NPC читается и при остановленном AI.

## Автоматически

- Python: провайдеры на подставных ответах, 503/тайм-ауты/квоты, Ollama think=false/выгрузка моделей, фоновые планы, отмена, чат, точная/массовая передача и реальные исходы шагов.
- C#: запрет управления человеком/чужим/мёртвым NPC, допуск действий по снимку, резерв нескольких стопок, защита квестовых вещей, commit только один раз, частичный отказ/уход получателя, этажи/наклон/повторы навигации, одна быстрая фраза следования, протокол/UI/маскировка ключей.
- Новые области: стабильные типы предметов, нормализация/экспорт каталога, передача до подтверждения и восстановление кеша, разбор предметного поручения и проверка выбранной цели/количества, правила маршрутизации E к NPC. Смысловые тесты используют подставные ответы модели.
- Wire probe: настоящий C#-сериализатор → Python HTTP → подставная модель → C#-декодер/политика. Сверяется общий каталог 41 действия и ограниченный набор NPC. PE-проверка запрещает прямые вызовы защищённого GetRightItem.
- HTTP smoke: запуск службы, сопряжение, авторизация, ошибки схемы, следование/стоп.
- Frozen smoke: упакованный EXE запускается без каталога исходников/Python; проверяются HTTP, статика, авторизация и версия. На Windows — дескриптор родительского процесса.
- GitHub CI проверяет Linux и Windows, собирает DLL/Windows ZIP и сверяет SHA256 перед релизом. Платных API-запросов нет.

**Среда проверки не запускает Valheim.** Эти проверки не подтверждают фактическое создание/отрисовку NPC, физику, смерть/сохранение и сетевое поведение на Valheim 1.0.21. Ссылочный SDK — 0.221.4; при несовместимости методов создание блокируется, журнал сохраняет стек.

## В игре

1. Закройте игру, замените весь каталог плагина из ZIP, включая runtime/_internal, удалите старую отдельную DLL. Запустите **один клиент** своим обычным персонажем. PowerShell/Python/браузер не нужны.
2. Войдите в свой тестовый мир либо запустите мир хостом. Esc/F8 → «Персонаж» → «Создать / найти NPC». Должен появиться отдельный Гоша с пустой сумкой, а ваш персонаж продолжить обычное управление.
3. Нажмите «Следовать». Ходите, прыгайте, вращайте камеру и пользуйтесь хотбаром человеком. NPC движется независимо; F9 останавливает только его. Набор чата/инвентарь человека не должен обрывать связь NPC; настоящая пауза одиночной игры останавливает физику.
4. Настройте Ollama и включите AI. Сравните точное «следуй за мной» и «Гоша, пошли»: второе должно попасть в сохранённый запрос AI. При долгом ответе UI показывает время, F9 отменяет.
5. Выполните [проверки предметов/путей](actions.md): 5 + 3 камня → передать 7, все камни, весь инвентарь, движущийся получатель, недоступный путь, квестовая вещь. Сопоставьте землю, сумку NPC, чат и отчёт.
6. Откройте свой инвентарь во время операций NPC. Он не должен закрываться, менять выбранный рецепт или получать вещи NPC. Проверьте сундук: доступ NPC/хост-владение, закрытое содержимое не видно; открытый человеком контейнер получает приоритет.
7. Проверьте крафт/ремонт с достаточными и недостаточными материалами/укрытием/уровнем станции. Строительство/ремонт строений/сон не должны выдаваться AI как доступные действия. При невозможном поручении нужна причина.
8. Сохраните и перезайдите. NPC должен остаться с теми же вещами; повторное создание — найти того же. Отойдите из области и нажмите создание: повторный NPC не должен появляться, окно покажет сохранённое место.
9. В тестовом мире проверьте смерть NPC: отдельное надгробие и вещи, человек не умирает/не возрождается; новый NPC — только явно и с пустой сумкой. Проверьте также сон человека: NPC не должен блокировать пропуск ночи.
10. С другим официальным клиентом проверьте видимость движения NPC, смену зон/лидера и чат «Только лидер / Все игроки». У подключившегося клиента создание на чужом мире должно отказать с понятным сообщением.
11. Проверьте разные разрешения/GUI scale, подсветку пункта Esc, вкладки и F8-резерв. Журнал/Диалог AI должны копироваться и сохраняться без ключей.

## Что отправить

Esc/F8 → «Журнал» → «Копировать отчёт» и **«Диалог AI → Сохранить обмен»**. Первый показывает версии, человеческого персонажа/NPC, планы, инвентарь и исключения; второй — фактический запрос, сырой ответ и проверку. Файлы отчётов — `BepInEx/config/ValheimAIHelper/reports`. Укажите поручение, результат на земле/в сумке и роль хост/подключившийся клиент. Ключи присылать не нужно.

Служба не стартует — проверьте полный runtime из ZIP. «NPC в незагруженной области» — вернитесь к указанному месту, автоматического призыва нет. Нет пути — NPC останавливается после ограниченных попыток, телепортации нет. 404/429 — полный ответ провайдера в журнале; 503 — ограниченные повторы и пауза. Медленная/слабая модель — время, фазы и токены/сек в «Журнал»; скорость не гарантирует правильное понимание задачи.

## Инвентарь и предупреждения 0.7.2

Эти сценарии требуют запуска настоящей игры; автоматическая сборка не подтверждает отрисовку и переносы в Unity.

1. Без настроенной модели подойдите к NPC и нажмите E. Повторите через Esc/F8 → «Персонаж» → «Инвентарь NPC». Должно открыться обычное окно с обеими сумками. Издалека кнопка должна сообщить, что нужно подойти, и не останавливать выполняемую задачу.
2. Передайте NPC стопку камней и заберите часть через разделение стопки. Сравните общее количество до и после; повторите для вещи с качеством, прочностью, вариантом и пользовательскими данными. Они должны сохраниться.
3. Заполните сумку получателя и попробуйте перенос и «Забрать всё». Непоместившийся остаток должен остаться у отправителя, без потери или дублирования. Сравните переносы квестовых предметов с обычным игровым окном; отдельная защита автономной передачи AI должна сохраниться. Правая кнопка по еде должна кормить человека, как при использовании из сундука.
4. Дайте NPC надеть оружие/броню, затем заберите надетую вещь обычным переносом и через «Забрать всё». У NPC не должно остаться снятого оружия/брони в руках или действующих бонусов. Не затронутое снаряжение должно сохраниться.
5. Откройте сумку во время следования и во время долгой генерации. NPC должен остановиться; новое поручение из чата не должно выполняться, пока идёт обмен. Закройте окно: продолжение возможно только после нового запуска следования/AI.
6. Проверьте закрытие при удалении более чем на 4 м, смерти NPC, смерти человека и выходе из мира. Сохраните и перезайдите после обмена: обе сумки должны содержать итоговые вещи, повторное «Создать / найти» — найти прежнего NPC.
7. Откройте обычный сундук и проверьте перенос, складывание и «Забрать всё». Изменения NPC не должны менять поведение мировых контейнеров или переключать локального игрока.
8. В начале BepInEx-журнала проверьте версию 0.7.2. Пройдитесь по Esc и несколько раз обновите наблюдения рядом с Pickable/ItemStand/Destructible: повторов предупреждений о поиске отсутствующих необязательных свойств/полей быть не должно. Другие предупреждения Harmony остаются видимыми; при повторе приложите полный журнал со строкой версии.

## Регрессии 0.7.1

- Локальный человек «Гоша», старый LeaderName «Бъёрн»: по умолчанию выбран человек этого клиента. Явный удалённый лидер при исчезновении не подменяется одноимённым.
- Наведение по Esc не переустанавливает кнопку. Откройте каждую вкладку дважды, измените масштаб; проверьте `ui-time`, журнал и его диалог.
- Сопровождение проходит переходы «подойти → удерживать → снова идти», не дрожит около порога и не требует генерации каждые 4/20 секунд. Новый чат должен обрабатываться.
- Ошибка предыдущего пути не отменяет блок/отступление при нападении. Пауза одиночной игры не исчерпывает бюджет шага.
- Пустая сумка, рядом выпавший камень/гриб и дерево: pickup работает без инструмента, gather не предлагается. Гриб-растение имеет interact; выпавший урожай затем pickup. Наличие/качество/поломка кирки изменяют доступность mining.
- Автотесты дополнительно проверяют 10 000 повторных обновлений UI с одним поиском типа и одним изменением подписи, частоту native-query gate, связанный private float-tick и новые правила инструментов. Реальная скорость UI/физика требуют игрового теста.
