# Valheim AI Helper

AI-напарник для Windows / Steam: **один клиент Valheim + отдельный NPC**. Ваш персонаж остаётся под вашим управлением. Меню: **Esc → Управление персонажем**, резервная клавиша **F8**, немедленный стоп NPC **F9**.

[Скачать Windows 0.8.4](https://github.com/S1mpleton/ValheimAIHelper/releases/download/v0.8.4/ValheimAIHelper-windows-0.8.4.zip) · [Релиз и исходники](https://github.com/S1mpleton/ValheimAIHelper/releases/tag/v0.8.4) · [SHA256](https://github.com/S1mpleton/ValheimAIHelper/releases/download/v0.8.4/ValheimAIHelper-windows-0.8.4.zip.sha256)

**В 0.8.4 исправлена проверка подключения AI:** кнопка проверяет доступность выбранной модели коротким обычным запросом. Составлять игровой план, выбирать действия или соблюдать JSON-схему для успешной проверки больше не требуется. [Изменения 0.8.4](docs/release-0.8.4.md) · **[Полный список 38 действий NPC](docs/actions.md)**.

Исправления 0.8.3 сохранены: после закрытия инвентаря прежняя работа продолжается без подключения модели заново; показана броня NPC и исправлен отправитель чата. Схема атомарных действий учитывает реальные доступные цели, а конфликтующие изменения задач и несовпадение разбора передачи допускают одно исправление моделью в общем бюджете ожидания. [Изменения 0.8.3](docs/release-0.8.3.md).

## Установка и запуск

1. Закройте игру. Установите [BepInExPack Valheim](https://thunderstore.io/c/valheim/p/denikson/BepInExPack_Valheim/), если его ещё нет.
2. Скопируйте **BepInEx из ZIP** в каталог с `valheim.exe`, заменив файлы плагина. Удалите старую отдельную копию `BepInEx/plugins/ValheimAIHelper.dll`, если она осталась вне папки плагина. Нужна вся папка `BepInEx/plugins/ValheimAIHelper`, включая `runtime/_internal`.
3. Запустите **одну** игру своим обычным персонажем. Откройте свой одиночный мир либо запустите мир как хост. **Python, PowerShell, браузер и второй аккаунт не нужны.**
4. Esc → «Управление персонажем» → «Персонаж». Задайте имя помощника (по умолчанию **Гоша**), нажмите **«Создать / найти NPC»**. Лидер по умолчанию — текущий локальный игрок; старое имя второго клиента игнорируется. Удалённого игрока можно выбрать явно. Повторное нажатие находит существующего NPC; новый инвентарь не копируется из профиля игрока.
5. **«Следовать»** работает без модели. Для AI откройте «Подключение AI», выберите Ollama / OpenAI / Gemini, получите список моделей, проверьте и сохраните подключение. Вернитесь в «Персонаж» и включите AI.
6. Поручения задаются в игровом чате. Настройки боя, еды и доступа «Только лидер / Все игроки» находятся в «Персонаж → Дополнительно».

Версия 0.7 меняет архитектуру. Персонаж старого второго клиента автоматически в NPC не импортируется. NPC начинает с отдельным пустым инвентарём: вещи можно передать через его окно инвентаря или поручить подобрать с земли. [Создание, сохранение, ограничения и проверка NPC](docs/npc.md).

## Общение

- **«Следуй за мной»** (также «Гоша, следуй за мной») — единственная быстрая фраза следования без модели.
- **«Гоша, пошли»**, «пойдём», «за мной», другие перефразировки — смысл определяет AI и выбирает действие. Пока ответ не получен, новая задача не превращается в следование по словарю синонимов.
- «Гоша, дай мне 5 камней», «Гоша, отдай все камни», **«Гоша, отдай мне все свои вещи»**.
- «Гоша, подбери выпавшее дерево», «Гоша, поешь», «Гоша, защити меня».
- Если в мире только один человек, его разрешённые сообщения поступают NPC напрямую: имя и префикс не требуются. Можно написать **«возьми топор»**, **«собирай одуванчики»** или **«не нужно больше собирать малину»**. При нескольких людях короткий классификатор определяет адресата по контексту, а имя NPC задаёт его явно. Смысл поручения затем разбирает AI. Человек и NPC различаются по роли и ID, даже если обоих зовут Гоша. Стоп/F9 остаётся немедленным; служебные статус/помощь доступны локально.

Проверяется настоящий сетевой отправитель. В режиме «Все игроки» выбранное моделью следование или точная быстрая фраза могут переключить лидера на отправителя. Сообщения разрешённых игроков могут отправляться выбранному провайдеру; ключ вводится в настройках, не в чат.

NPC отвечает в игровом чате под собственным именем, например **«Гоша: [AI] …»**. Ответ виден владельцу мода как сообщение другого персонажа и не превращается в новое поручение от человека. Чтобы имя NPC правильно отображалось в журнале чата другого участника, мод нужен и на его клиенте. Клиент без мода может показывать имя аккаунта хоста из штатного списка игроков; сетевое имя NPC и его надголовный текст при этом передаются.

## Планировщик задач

Начиная с 0.8.0 NPC хранит **до 15 активных задач** с приоритетами и зависимостями. AI разбирает поручение на задачи, задаёт каждой новой задаче приоритет и нужные зависимости. Мод проверяет план, выбирает доступную задачу по указанному приоритету и исполняет её по свежему состоянию игры. Автоматического назначения приоритета по типу задачи или повышения следования при удалении лидера нет. Подбор каждой следующей ягоды и устойчивое следование не требуют нового ответа модели. Другие цели, например последовательность крафта, могут потребовать дополнительных обращений к AI.

Например, **«Гоша, следуй за мной и собирай малину по пути»** становится постоянным следованием и сбором в коротких обходах рядом с лидером. **«Гоша, собери 5 камней и дай их мне»** — сбором нужного количества и зависимой передачей. AI предлагает структуру; прогресс и завершение подтверждает игра.

Откройте **Esc/F8 → Управление персонажем → Задачи**: здесь видны приоритет, состояние, прогресс, цель и причина ожидания. Можно поставить на паузу или продолжить задачу/весь пул, отменить работу и изменить приоритет. Выполненные и отменённые задачи доступны в истории. При переполнении новый план отклоняется целиком, без вытеснения старых задач. В 0.8.1 одинаковое следование и одинаковые задания сбора объединяются; старые сохранённые дубли также сводятся к одной задаче. Название берётся из настоящего типа задачи, поэтому следование не получает заголовок «Малина по пути». Равные по приоритету задания сбора получают ход после подтверждённого шага, сохраняя уже начатый подход.

Кнопка **«Показывать задачи справа»** включает небольшую панель поверх игры: текущая задача и следующие четыре, их приоритеты и состояния. Настройка сохраняется. Панель скрывается при открытии меню и не перехватывает управление персонажем.

Новое обращение **не ставит прежнюю работу на паузу**. NPC продолжает её, пока модель разбирает просьбу; проверенный план применяется по свежему наблюдению. Уже начатая передача сначала получает результат игры. Ошибка нового плана оставляет прежние задачи. Можно попросить отменить только сбор малины, сохранив следование.

**F9 / «Стоп» отменяют весь пул.** Открытие инвентаря временно приостанавливает исполнение до закрытия; уже поставленные вручную на паузу задачи не возобновляются автоматически. Смена провайдера сохраняет задачи на паузе. Пул сохраняется отдельно для мира и NPC в `BepInEx/config/ValheimAIHelper/task-pools`; смена процесса игры больше не меняет папку задач. Старые сохранения из `runtime-*/task-pools` переносятся с проверкой мира и NPC, без удаления старых файлов и замены уже существующего стабильного сохранения. После загрузки задачи остаются на паузе до явного продолжения. [Приоритеты, состояния и сценарии проверки](docs/task-scheduler.md).

## Предметы и навигация

**Инвентарь NPC:** подойдите к помощнику и нажмите **E** либо откройте **Esc/F8 → Персонаж → Инвентарь NPC**. Предпочтительно открывается штатное окно игры, как при обмене с сундуком: видны ячейки человека и NPC. Если адаптер игрового окна недоступен или окно не стало видимым, автоматически открывается резервное окно с двумя настоящими инвентарями, иконками, количеством и переносом в обе стороны. В нём выберите предмет и количество либо используйте Shift + нажатие для всей стопки. Экипировка NPC отмечается бело-серым; синяя отметка вашего персонажа сохраняется. Для открытия нужно находиться не дальше 3,5 м; обмен доступен человеку на клиенте-хосте и не требует модели или API.

В 0.8.1 нажатие E ставит запрос в очередь; открытие выполняется после выхода из игрового обработчика взаимодействия. Журнал `npc-inventory` отмечает запрос, проверки, штатный либо резервный путь и закрытие. При проблеме приложите эти строки.

В штатном окне рядом с ячейками NPC отображаются значок щита и его реальная броня; в резервном окне значение показано у заголовка сумки. Учитываются надетые вещи и игровые эффекты, а не все предметы в сумке. Показатель брони человека остаётся отдельным.

Открытие временно приостанавливает исполнение NPC, сохраняя режим, задачи и подтверждение уже начатой операции. После закрытия прежняя работа продолжается без повторного подключения модели. F9, ручная пауза, смена провайдера, смерть или выход из мира не отменяются закрытием окна. При удалении дальше 4 м обмен закрывается. Используется тот же инвентарь NPC с обычным сохранением вещей; перемещаемое снаряжение сначала снимается с NPC.

Если после 0.8.2 пул уже сохранён на постоянной паузе, один раз нажмите **«Задачи → Продолжить всё»**. Обновление сохраняет прежнюю паузу; следующие открытия и закрытия инвентаря используют временную остановку. Подключать модель заново не нужно.

Правая кнопка по еде в штатном окне кормит вашего персонажа. Для еды NPC положите продукты в его сумку и используйте автоматическую еду или поручение в чате.

Выпавшие вещи (`pickup`) не требуют инструментов. Растения собираются через `interact`, деревья/залежи — через `gather` с подходящим инструментом. Гриб не выдаётся за добываемую залежь из-за наличия Destructible. [Как устроены навыки и атомарные шаги](docs/skills.md).

**Каталог предметов** строится из базы установленной игры, включая зарегистрированные другими модами предметы. Полный читаемый список находится в `BepInEx/config/ValheimAIHelper/item-catalog.json`: ID prefab, название на текущем языке, токен локализации и категория. Каталог описывает типы вещей; доступность для поручения подтверждается сумкой и наблюдаемым миром. [Как AI выбирает предмет и что проверяет мод](docs/items.md).

Для нового поручения модель выбирает типы предметов из игрового каталога при составлении пула. Затем выбор целей ограничивается подходящими вещами из снимка: запрос малины допускает соответствующие ягоды/кусты, а отсутствие топора приводит к ответу с причиной. Фаза `tasks` видна в «Журнал → Диалог AI»; сложные цели используют фазу `task-step`. Все обращения к Ollama сохраняют `think=false`. Скорость и правильность понимания всё ещё зависят от модели.

Передача и сброс сверяются отдельным запросом с исходным поручением, типами вещей и количеством (`task-transfer`). Выбор передачи всего инвентаря проверяется отдельно (`task-scope`). Если он не подтверждён, новый план отклоняется. Точное количество и передача всех вещей одного вида остаются отдельными вариантами. При несовпадении разборов выдача не начинается: модель может один раз исправить весь новый набор задач с учётом исходной просьбы и результатов независимой проверки. Затем передача проверяется снова. Это тот же единственный повтор `tasks-repair` в пределах исходного тайм-аута; код не подменяет выбранные AI предметы или количество. Если разборы снова не согласованы, прежний пул сохраняется, а причина попадает в чат и журнал.


NPC наблюдает загруженные выпавшие `ItemDrop` и собираемые через E объекты `Pickable`/`PickableItem` до 128 м. Общий список ограничен 80 целями с сохранением разных типов: множество ягод не должно вытеснять ближайший топор. Для предметов через E передаются объявленный тип результата `produces` и стабильный prefab; они не требуют инструмента для добычи. Невидимые и ещё не загруженные сетевые объекты не раскрываются. Закрытый сундук не раскрывает содержимое.

Передача: **подойти к текущему положению получателя → остановиться рядом → сбросить количество → проверить изменение инвентаря**. Это предметы на земле, которые получатель подбирает обычным способом. Точное количество может охватывать несколько одинаковых стопок; «все камни» и «все вещи» исполняются одной проверяемой составной операцией. Квестовые предметы сохраняются. При частичном отказе сообщается реальное количество; исходная выдача автоматически не повторяется.

Следование удерживает дистанцию 2,5–4 м и отслеживает лидера в загруженной области до 128 м. Навигация использует штатную сетку путей, повторяет поиск, проверяет близкие подходы и фактическое продвижение. NPC не телепортируется к лидеру и не проходит сквозь препятствия. Для невыполнимого пути в чате появляется причина. [Действия и сценарии проверки](docs/actions.md).

## Ollama и диагностика

Ollama получает читаемые ID с названиями предметов; мод сохраняет исходные игровые ID. Завершённая передача/ответ не повторяются автоматически; планировщик переходит к следующей доступной задаче. Когда задач нет, он ожидает нового поручения.

Ollama работает на том же ПК, стандартный адрес `http://127.0.0.1:11434`, API-ключ не нужен. Модель загрузите заранее в Ollama. Все запросы используют **think=false**. При смене модели служба сначала выгружает остальные запущенные модели Ollama; веса не удаляются. [Подробности](docs/ollama.md).

**«Проверить подключение»** проверяет доступность выбранной модели и получение непустого ответа на короткий обычный запрос. JSON-схема, игровые действия, каталог и наблюдения NPC не отправляются; компилятор и пул задач не вызываются. Даже ответ `{"tasks":[]}` подтверждает, что модель ответила, и не проверяется как игровой план. Успех означает доступное подключение, а не умение выполнять все поручения. В Ollama проверка использует до 16 выходных токенов и контекст 1024; игровой контекст 16384 не меняется. Ошибки Ollama показывают HTTP-код и ответ сервера: проблема памяти, отсутствующая модель и отказ `think=false` различаются. Сообщение об отказе `think=false` появляется только при явном отклонении этого параметра; размышления автоматически не включаются.

Снимки мира обновляются примерно раз в секунду, минимальный интервал запросов модели — 20 секунд по умолчанию. Устойчивое следование не вызывает модель по одному только таймеру; новые сообщения обрабатываются. Ожидание локальной генерации — до 300 секунд. Во время разбора нового поручения прежняя работа продолжается; после принятия плана следование и сбор не ждут модель на каждом шаге. Планировщик всех провайдеров получает полный формат задач с обязательным приоритетом новой задачи. AI сам выбирает состав плана и зависимости; готовые задания с малиной и нативные шаблоны для слабой модели не подставляются. Маленькая модель может быстро отвечать правильным JSON и ошибаться в смысле поручения. Скорость/фазы запроса и токены/секунду видны в «Персонаж» и «Журнал».

С 0.7.1 UI не пересканирует типы/иерархию при каждом наведении. Вкладки строятся по мере открытия; строки `ui-time` показывают время окна.

Повторы `HarmonyX: AccessTools.Property/Field: Could not find…` из присланного отчёта возникали при проверке необязательных полей разных версий игры. Такие проверки выполняются без предупреждений и с кешированием, включая поля меню Esc. Остальные предупреждения Harmony не отключены. В 0.8.2 уведомления об обмене также учитывают необязательные параметры методов игры и используют запасной путь через HUD; логика самого переноса вещей не переписана. После обновления в начале журнала должна быть версия **0.8.4**; если видна старая, проверьте, не осталась ли отдельная старая DLL.

В отчёте выпавшие вещи и объекты сбора через E перечисляются отдельно: `dropped items` и `E collectibles`. Это помогает отличить отсутствие наблюдения от неверного выбора модели.

**Журнал → Диалог AI** показывает отправленный контекст, сырой ответ и результат проверки без нового запроса модели. Неверный план показывает поле и причину, например `$.tasks[0].item_prefabs`; единственное исправление моделью видно отдельной фазой `tasks-repair`. Есть копирование и экспорт. **Журнал → Копировать отчёт** включает версии, NPC/человека, действия, инвентарь и исключения; ключи маскируются. Если действие не выполняется, приложите отчёт и экспорт соответствующих фаз `tasks` / `tasks-repair`. [Просмотр диалога](docs/dialogue.md).

Служба из архива запускается модом и завершается с игрой. API-ключи хранятся только в памяти; Ollama и её веса в ZIP не входят. Ошибки нового запроса 404/429 не применяют новый план: причина попадает в чат/журнал, прежние допустимые задачи сохраняются. Облачный 503 повторяется с паузами 2/4 секунды и затем не менее 15 секунд ожидания. F9 отменяет ожидающие запросы.

## Границы версии

NPC доступен **в одиночном мире и у хоста**. Подключившийся клиент не создаёт NPC на чужом или выделенном сервере. У NPC собственные игровые данные и надгробие; вход в другой мир не переносит инвентарь. Удалённого NPC нельзя пересоздать, если его область не загружена: вернитесь к сохранённому месту.

Из общего каталога 41 действия NPC объявляет **38** (меньше при выключенном бое). Строительство, ремонт строений и самостоятельный сон через кровать в 0.7 недоступны: прежние реализации зависели от камеры/интерфейса локального игрока. NPC не мешает хосту пропускать ночь. Крафт/улучшение и ремонт выполняются без окна игрока с проверкой ресурсов и станции; особые рецепты с выбором одного ингредиента пока отклоняются. Сундук должен быть доступен NPC и принадлежать сетевому хосту; открытый человеком сундук получает приоритет. Рыбалка, торговля и корабельный автопилот не реализованы; телепортация NPC через порталы запрещена.

Сборка использует ссылочные библиотеки **Valheim 0.221.4**. Автотесты, Linux/Windows CI и запуск упакованной службы проверяют код и протокол, **игровой запуск Valheim 1.0.21 здесь недоступен**. Жизненный цикл NPC, физика, внешний вид и кооператив требуют проверки в игре по [сценариям](docs/testing.md).

## Разработка

Python 3.12, .NET SDK из `global.json`, Node.js для дополнительного веб-интерфейса:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install --require-hashes -r bridge/requirements-dev.txt
PYTHONPATH=bridge/src .venv/bin/python -m pytest bridge/tests -q
.venv/bin/python scripts/smoke_bridge.py
python3 scripts/bootstrap_mod.py
dotnet test mod/ValheimAIHelper.Tests/ValheimAIHelper.Tests.csproj -c Release -p:RestoreLockedMode=true
dotnet build mod/ValheimAIHelper/ValheimAIHelper.csproj -c Release -p:RestoreLockedMode=true
.venv/bin/python scripts/check_wire.py
```

Для внешнего моста выключите `Bridge.AutoStart`; разработческий запуск: `PYTHONPATH=bridge/src .venv/bin/python -m valheim_ai`. `start-windows.ps1` оставлен для разработки; пользователь ZIP его не запускает.

На Windows: `python -m pip install --require-hashes -r bridge/requirements-build.txt`, затем `python scripts/freeze_bridge.py`, `python scripts/smoke_frozen.py .local/frozen/ValheimAIBridge/ValheimAIBridge.exe`, `python scripts/package.py --runtime .local/frozen/ValheimAIBridge`. CI публикует ZIP после проверок обеих ОС. Игровые, Unity и BepInEx DLL не входят в архив.
